2026-10-13
==============================================================================
Trust upgrades to the manual payment screens  (committed, not yet pushed)
- Pay screen: order recap (items, total, delivery address, phone), "Chat with us before
  you pay" WhatsApp button carrying the order reference, tap-to-copy Till number and
  amount, and a safety check showing the name M-Pesa should display before the PIN.
- Confirm step: paste the M-Pesa SMS and the code and amount are filled in automatically
  (checked against a real Till payment SMS); typing the details is still available.
- Final page: delivery estimate, the customer's phone and address, and a "Send my receipt
  to WhatsApp" button that opens a chat with their order summary.
- Shop details are settings, not code: NEXT_PUBLIC_TILL_NAME ("Elisha Njeche"),
  NEXT_PUBLIC_ORDER_HOLD_TIME ("30 minutes"), NEXT_PUBLIC_DELIVERY_ESTIMATE ("within 2
  hours"). Defaults live in .env.production; a Netlify variable of the same name overrides
  them. Anything left blank is simply omitted from the page.
- Intended as the stand-in while the Till prompt is fixed, and as a fallback if the Till
  ever has problems again: turn the automatic prompt on or off with
  NEXT_PUBLIC_MPESA_PROMPT_ENABLED.
- Note: the hold time is a promise on the page only; nothing cancels unpaid orders
  automatically.

Clearer checkout steps  (committed, not yet pushed)
- Checkout now shows progress: 1 Your details -> 2 Pay with M-Pesa -> 3 Confirm payment.
- Customers were pressing the order button repeatedly and creating duplicate sheet rows
  because nothing told them what to do next. After placing an order the form is replaced
  by a "pay to complete your order" screen, so there is no second button to press.
- Skips the automatic M-Pesa prompt (and its "Failed to send a request to the Edge
  Function" error) until NEXT_PUBLIC_MPESA_PROMPT_ENABLED=true, which should only be set
  once the PayHero functions are deployed. Wording no longer promises instant payment.
- Success page now lists what happens next (we confirm payment, contact you about
  delivery, deliver) and shows the order reference.

Admin edits now reach the live site
- Created a Netlify build hook and set NEXT_PUBLIC_DEPLOY_HOOK_URL in Netlify, so
  saving a product or category in /admin triggers a rebuild automatically (about a
  minute until the public pages update). No code change was needed; the hook code
  (lib/deploy.ts) already existed.
- Cause of "price edits don't work": the edits WERE saving to the database, but the
  public site is a static snapshot and nothing was telling Netlify to rebuild.
- Note: a brand-new product has no Edit page on the live site until the next rebuild.

2026-10-12
==============================================================================
Manual M-Pesa payment confirmation  (9b8b624, pushed 2026-10-13)
- Checkout no longer dead-ends on "Failed to send a request to the Edge Function".
- Every order gets a reference, e.g. CV-261012-K7QF.
- If the automatic M-Pesa prompt can't be sent, the customer sees the Till steps and
  a form for their M-Pesa confirmation code, the number they paid from, and the amount.
- Google Sheet gets two rows per order sharing the reference:
    "[REF] AWAITING PAYMENT" and "[REF] PAYMENT CLAIMED · M-Pesa code ...".
  The existing sheet script works unchanged. The code is a customer claim; staff must
  check it against the Till statement. See docs/GOOGLE_SHEETS_WEBHOOK.md.
- Success page shows the order reference.

Supabase config moved into the project  (d850052, live)
- The Netlify dashboard value for NEXT_PUBLIC_SUPABASE_ANON_KEY was being baked into
  the build as masked bullet characters, which broke login ("String contains non
  ISO-8859-1 code point") and made the build fall back to the old 101-product catalog.
- The public Supabase URL + anon key now come from .env.production. The service_role
  key is never stored in the project.

Cookie consent + analytics  (67442a0, live)
- Cookie banner with Accept / Decline of equal prominence, using Google Consent Mode
  v2: analytics starts denied and is only granted after Accept. The choice is
  remembered, and a "Cookie settings" link in the footer reopens it.
- Optional second GA4 property via NEXT_PUBLIC_GA4_ID_2 (reports to both; one script).
  Netlify still uses the original NEXT_PUBLIC_GA4_ID (G-MFWXN0QPWV).
- Product colours stored as plain text are now ignored instead of breaking swatches,
  the colour filter and the cart colour picker.
- Categories with no image (e.g. Sneakers & Shoes) show the placeholder image.
